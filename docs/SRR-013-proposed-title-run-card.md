# SRR-013 proposed responsive title-card observation

**NOT AUTHORIZED.** This card is for maintainer review. It requires a separate
written authorization that identifies the approved reader, build, operator,
private evidence destination, and permitted checkpoint.

1. Pin the frozen and independently reviewed reader and the approved
   Starfield 1.16.244.0 executable identity from the [acquisition evidence](SRR-012-acquisition-evidence.md).
   Establish the exact path, session and Steam attribution, mapped-image
   identity, load order, overrides, and the effective inputs for the four
   [predeclared samples](SRR-012-sample-plan.md). Arrange a private evidence
   destination with sufficient space and a retention and redaction decision.
2. For the single observation, have the operator show the visible title card
   and demonstrate responsiveness before advancing. Bind their `title` marker
   to the process epoch, UTC anchor and monotonic clock. Hold the phase and
   identify the marker evidence in the private record.
3. Within the authorized marker window collect and revalidate the selected
   component ranges twice. Authenticate the same process, mapped image,
   context and registry before and after each collection. Keep partial or
   rejected receipts with precise causes. If the phase, process, structure or
   values change, invalidate the window and require a fresh marker before any
   additional observation covered by the authorization.
4. Seal and hash the bounded evidence, close the reader and report each of
   the four outcomes independently. Retain PID, epoch, paths, addresses and
   raw selected bytes privately. Scope a zero result to its component and
   marker window. Agreeing pairs can miss intervening mutations or coincide
   with a cleared intermediate state. The evidence cannot establish execution
   timing, persistence, or save serialization.

This observation requires no travel or save load. Select the save and
checkpoints on scientific grounds if a later state-only comparison is
authorized. For a separate experiment requiring travel, plan around Save52,
including travel to Decaran VII-b. Treat its save state and checkpoint
comparability explicitly. Before any authorized live use of Save52, obtain
specific approval to copy and use it. Verify a separate retained copy under
`.local-work/release-assets/` using the existing Save2 custody and protection
pattern and pin the original, backup and retained-copy identities and hashes.
