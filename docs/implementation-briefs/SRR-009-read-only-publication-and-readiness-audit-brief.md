## Questions to answer

**A. Stage A readiness (primary; report first).** Can the already reviewed Phase 1 candidate proceed to *separate* Stage A authorization without any unacknowledged missing input or unreproducible operational dependency? Audit the exact run card and transitive references it invokes: compiler/observer binary and source pin, `stage_a_marker.py`, environment/protection scripts (notably any SRR-008 scripts under `.local-work/`), Python/toolchain prerequisites, manifests, Steam attribution files, local evidence directories, permission/interactive-account assumptions, operator inputs and authorized recovery controls. Identify which resources must exist *at run time*, which are only historical references, and which would be impossible to reconstruct. Check the actual existence and hashes of declared required local inputs where read access is available. Distinguish a Stage A blocker from a documentation or publication issue; don't treat benign Steam/client version drift as a blocker. Preserve strict critical executable/ntdll/mapping and debugger ownership gates. Note the `__COMPAT_LAYER` and foreign-DR evidence with their correct qualifications. Do not infer that offline fixtures prove live retail attachment.

**B. Publication/dependency audit (separate disposition).** Inventory the entire `.local-work/` dependency surface *relevant to tracked project material* (not an undifferentiated dump of every temporary file). Inspect references from tracked source, scripts, research dossiers, documentation indexes, build/reproduction commands, release/publication assertions, and links; recursively follow significant referenced local inputs and derivations. For each dependency or evidence class, identify exact path/pattern, tracked versus ignored/untracked status, consuming claim/procedure, whether it is source, generated artifact, primary evidence, historical review, private operational record or third-party payload, reconstructability and requirements for a clean clone. Inspect the declared public reproduction route from a fresh-checkout perspective, including lawful externally obtained game/system binaries and toolchain requirements. Identify hidden scripts/helpers that would prevent reproduction, especially the SRR-008 protection/environment scripts. Distinguish (1) dependencies that should be tracked as non-sensitive reusable code, (2) essential local evidence whose absence limits public verification, (3) replaceable generated artifacts, (4) intentionally private sensitive material, and (5) nonredistributable proprietary material. Do not assume every raw journal must be published; classify claims as independently reproducible, historically verifiable only with retained local receipts, or presently unsupported. Provide a minimal proposed remediation for each actual defect, without implementing it.

**C. Custody and consistency.** Check correspondence of the final task patch, frozen source hashes, manifest, challenger review and dossier claims, as far as read-only inspection permits. Identify broken links or unsupported references, contradictory versions/dispositions, untracked runtime prerequisites, accidental private-path/account disclosures in prospective public files, copyright/license issues and unqualified publication claims.
